# Reporting and PDF Generation

## Purpose

CyberShield reports are intended for small businesses, technical owners, and consultants who need a clear summary of the assessed website posture. The report is a faithful snapshot of verified CyberShield data and is not a substitute for a broader security audit or enterprise SOC workflow.

## Architecture

The report flow is intentionally simple and grounded in the project architecture:

Database -> Business / Website -> Scan -> Verified Findings -> Deterministic Risk Engine -> Report Snapshot -> PDF Artifact

The report is generated server-side. User input is used only to select the business, website, or scan scope. The server builds the final content from the database and does not accept arbitrary findings or evidence from the client.

## Lifecycle

Reports are created in a deterministic lifecycle:

- pending: the request is accepted
- generating: report data and the PDF artifact are being built
- completed: the snapshot and PDF are finalized
- failed: generation failed and the report is left in a failed state without leaking internal details

## Snapshot semantics

Reports are created from a consistent, immutable snapshot. The snapshot captures the selected scope, current finding set, risk score, risk model version, and the report metadata used to build the PDF. Once generated, the report is treated as a historical record of the evaluated state.

## Data sources

The report uses the same data already stored by CyberShield:

- business metadata
- website information
- scan metadata
- finding metadata including title, severity, status, description, evidence, recommendation, and occurrence history
- the deterministic risk model version and score

The report does not invent vulnerabilities, CVEs, technologies, or remediation results. If a field is missing in the actual assessment data, it is omitted from the report instead of being guessed.

## Risk and findings

The report uses the existing Day 7 risk engine. It preserves the risk model version and the risk score that was computed for the selected assessment scope. Finding severity and status are copied directly from the verified database record.

## PDF generation

PDF generation is handled by a lightweight backend service that writes a controlled report file into the application report directory. The PDF content includes the CyberShield heading, report metadata, executive summary, findings table, detailed evidence sections, and a limitations statement. The generated output is kept readable and free from stack traces or raw JSON dumps.

Long finding content is wrapped across pages, summary tables repeat their headings, and generated PDFs include page numbers. Missing findings and optional scan/evidence fields are represented safely. Finding text is escaped before PDF rendering so stored content cannot be interpreted as report markup.

## Storage and download

Generated PDFs are stored under a controlled directory for the application and are served through an authenticated, owned report download route. The file name is generated by the application and the route resolves the file against the storage root to prevent path traversal.

## Report Center

The authenticated Report Center uses `GET /api/v1/reports` to show report history. Results are restricted to businesses owned by the signed-in user and are returned newest first by default. The endpoint supports bounded pagination with `page` and `page_size`, title/type search with `search`, website filtering with `website_id`, status filtering with `status`, and `sort=newest|oldest`.

Report Center list responses include safe report metadata such as status, timestamps, risk score, PDF availability, finding count, severity summary, and scan summary. Full finding snapshots are available only from the authorized report detail endpoint. The UI provides loading, empty, error, search, filter, pagination, detail, and PDF download states.

## Authorization and integrity

Report creation, report listing, report detail, and report download all enforce the same business ownership model as the rest of CyberShield. A user cannot access another user’s report or download a PDF for a cross-business assessment.

When both website and scan scope are supplied, the backend also requires the scan to belong to that selected website. Client-supplied scope identifiers never override the server-side business relationship checks.

Report snapshots redact credential-like values such as API keys, bearer tokens, cookies, passwords, secrets, and JWT-shaped values from finding text before exposing the snapshot or rendering the PDF.

## AI-assisted content

If AI guidance is included in a report, it must be clearly labeled as AI-assisted guidance and remain grounded in the actual finding and the verified evidence. AI must never change severity, invent evidence, or claim a remediation was successful without verification.

## Limitations

This report reflects the checks and evidence collected by CyberShield during the specified assessment. It does not claim complete security, guarantee protection, or provide a full penetration test. CyberShield reports are designed to support informed remediation, not absolute assurance.
